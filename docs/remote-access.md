# Доступ к Depo из интернета: проводник и скрытый сайт

Depo живёт дома: на Raspberry Pi, мини-сервере или ноутбуке. Без настроек он виден только в локальной сети и в NetBird. Чтобы открывать его с любого телефона по обычному `https://ваш-домен`, ставится **проводник** — недорогой VPS, который сам состоит в NetBird.

```
телефон ──https:443──▶ depo.example.org  (VPS: Nginx Proxy Manager + Let's Encrypt)
        ──▶ socat (forward-web) ──туннель NetBird──▶ Depo :4620 дома
        ──▶ socat (forward-ip, :4621) ──▶ Depo :4621 (вход по https://IP с сертификатом Depo)
```

Наружу открыт только 443. Домашний сервер не получает белого IP и не открывает портов.

## 1. Проводник

1. В панели NetBird создайте Setup Key для сервера.
2. На VPS с Docker скопируйте [`deploy/relay/docker-compose.yml`](../deploy/relay/docker-compose.yml) в `/opt/depo-relay/`. Рядом положите `.env` со строкой `NB_SETUP_KEY=…` (права 600).
3. Замените `100.x.y.z` на адрес Depo в NetBird. В «Настройки → Доступ» он уже подставлен.
4. Запустите и проверьте:
   ```sh
   cd /opt/depo-relay && docker compose up -d
   docker exec depo-relay-netbird netbird status
   ```
   Пересыльщики открывают порты, только когда Depo отвечает на `/api/remote`, то есть когда у него есть выключатель доступа.
5. DNS: A-запись домена → публичный IP VPS.
6. Обратный прокси. В Nginx Proxy Manager заведите Proxy Host на `http://<шлюз docker>:14620` с Websockets, Let's Encrypt и Force SSL. В Advanced добавьте `proxy_buffering off; proxy_read_timeout 1h;`, иначе лента ответов придёт рывками. Хост можно завести и скриптом [`deploy/relay/npm-add-host.mjs`](../deploy/relay/npm-add-host.mjs). Для своего nginx или Caddy настройка та же: TLS на домене, `proxy_pass` на 14620, буферизация выключена.

Подробно, с откатом — в [deploy/relay/README.md](../deploy/relay/README.md).

## 2. Настройка в Depo

«Настройки → Доступ»:

| Поле | Что это |
|---|---|
| Домен | `depo.example.org`. Запросы на этот домен Depo считает «внешними». |
| IP проводника | Публичный IP VPS. Depo сам добавит его в свой сертификат (`lib/tlscert.mjs`), и вход по `https://IP:4621` заработает без переустановки CA на телефоне. |
| Секретный адрес входа | По умолчанию `/enter`. Поменяйте на свой, например `/door-7f3k`. |
| Порог неверных паролей | От 1 до 5. После стольких ошибок подряд удалённый доступ выключается сам. |

Нажмите «Проверить снаружи» и включите тумблер. Переключать доступ можно и из Telegram-бота.

## 3. Как выглядит Depo снаружи

| Запрос без входа | Ответ |
|---|---|
| `/` | Сайт-визитка из [`public/site/`](../public/site/index.html). Замените его своим, сохранив имя `index.html`; файлы рядом отдаются по `/site/…`. |
| секретный адрес | Страница входа: пароль, затем код из Telegram на новом устройстве. |
| любой другой адрес | Пустой 404 без имени и версии сервера. |
| `/api/*` | Пустой 401. |
| доступ выключен | Пустая страница на любой запрос. |

Изнутри (локальная сеть, NetBird) Depo работает как обычно, сайт и секретный адрес на это не влияют.

## Безопасность

- Ограничение попыток входа считает настоящий IP клиента. `X-Forwarded-For` принимается только от проводника.
- Снаружи всегда отдаются HSTS, `nosniff`, `X-Frame-Options: DENY` и `no-referrer`.
- На новом устройстве вход подтверждается кодом из Telegram (`lib/twofa.mjs`), а на телефоне можно включить пин-код и отпечаток.
- Пароль Depo должен быть длинным и уникальным. Пароли от VPS и Nginx Proxy Manager храните отдельно и не пересылайте в чаты.
